# Workout & Strength Analytics API

REST API для учёта тренировок, подходов и автоматического расчёта силовых объёмов (килограммов) спортсменов.

## Структура репозитория
* api.yaml — спецификация контракта в формате OpenAPI 3.0.
* swagger_server/ (и сопутствующие файлы сервиса) — сгенерированный каркас серверного приложения на Python (Flask).
* README.md — описание назначения API и процесса разработки.

## Как проектировали и генерировали

1. Проектирование контракта (API-first):
   Спецификация api.yaml спроектирована с помощью LLM (Gemini) по предметной области «Хранилище тренировочных данных и нагрузок» и проверена на валидность в Swagger Studio.
   * Использованный промпт: описана структура сущностей БД (clients, exercises, workouts, sets) и поставлена задача составить OpenAPI 3.0 спецификацию на 5 эндпоинтов с разными HTTP-глаголами (GET списка, POST, GET детализации с аналитикой, PATCH, DELETE), кодами ошибок (400, 401, 403, 404) и разделением входных/выходных DTO.
   * Ручные правки: уточнены ограничения валидации (minimum: 1, maximum: 10 для RPE), добавлено разделение подходов на warmup и working через enum, поправлены переносы строк в описаниях ответов, а также вынесены расчётные поля (working_tonnage_kg, working_sets_count, set_tonnage_kg) в выходные DTO-схемы, чтобы внутренние поля БД не утекали наружу.

2. Кодогенерация сервиса:
   Каркас бэкенда на Python (python-flask) сгенерирован по валидной спеке через встроенный генератор Swagger Studio (Codegen -> Server Stub -> python-flask, аналог команды openapi-generator-cli generate -i api.yaml -g python-flask -o service).
